## 当前范围

- `/chat/question` 的普通提问、重新生成，以及 `/mcp/mcp_question` 使用请求占位和会话锁。
- `/chat/record/{record_id}/{action_type}` 的分析、预测接口没有 request_id，只参与会话互斥，不生成兜底 request_id。
- 启动向量任务的 PostgreSQL 咨询锁保持不变。推荐问题生成等辅助任务不在本次两个锁的保护范围。

## 两个锁

| 用途 | 键 | 值 |
| --- | --- | --- |
| 请求占位 | `sqlbot:local:request:processing:{chat_id}:{request_id}` | 每次抢锁尝试生成的新 owner_token |
| 会话互斥 | `sqlbot:local:chat:lock:{chat_id}` | 同一次执行使用同一个 owner_token |

使用 `SET ... NX PX` 原子获取锁与设置租约。续期 Lua 先核对两个键的持有者，再一起延长 TTL；任意一个不匹配则不续期。释放 Lua 只删除自己仍然持有的键。当前按单 Redis 实例设计，未支持 Redis Cluster 的跨槽多键脚本。

默认配置（无需为默认值修改 `.env`）：

```dotenv
IDEMPOTENCY_LOCK_TTL_SECONDS=60
IDEMPOTENCY_RENEW_INTERVAL_SECONDS=20
IDEMPOTENCY_TASK_MAX_SECONDS=600
```

600 秒是可调整的开发期推进时限，包含排队和准备时间，并非已有耗时数据得出的生产阈值。达到时限后停止续期和后续推进，不能强行终止 Python 线程或已经发出的外部请求。

## 入口与状态

先做权限检查，再竞争请求占位，再竞争会话锁。创建问答记录、初始化执行服务均在取得锁后进行。

| 状态/错误码 | 处理 |
| --- | --- |
| NEW | 已接单，准备提交后台任务；仅为内存状态 |
| PROCESSING | HTTP 409，同一请求已有占位，本次重复请求停止 |
| CHAT_BUSY | HTTP 409，其他请求占用会话，释放本次请求占位后返回 |
| COORDINATION_UNAVAILABLE | HTTP 503，Redis 未配置、通信异常或应用正在关闭，不绕过门禁执行 |
| RUNNING | 后台任务已提交 |
| SUCCESS / FAILED | 后台任务结束后的内存状态，不写成功缓存或状态表 |
| LOST | 租约丢失、续期通信失败或超出推进时限，阻止后续调用与保存 |

前端会显示门禁错误；普通问数遇到 CHAT_BUSY 时，若输入框仍为空，会恢复本次问题文本，不自动等待或重试。

## finally 与责任交接

1. 提交线程池任务之前，入口异常或取消由入口清理已取得的锁。
2. 提交成功后，独立的异步观察任务等待真实线程池 Future 结束，接管清理责任。
3. HTTP 返回、浏览器断开或停止接收响应，不代表线程结束，不能提前释放。
4. 线程执行结束并完成原有结果保存后，观察任务在 finally 中停止并等待续期退出，先释放会话锁，再释放请求占位。
5. 一把锁释放失败仍尝试释放另一把；记录清理错误，剩余占位依赖 TTL 回收。
6. 应用关闭时撤销执行资格并停止续期。尚未结束的线程不会被视为已完成，保留占位等待 TTL；正常结束的任务仍走清理。

MCP 非流式结果收集已改到线程中等待，避免它阻塞应用事件循环和 Redis 续期。Redis 客户端始终在应用事件循环使用；LLM 线程只检查本地租约状态与时间。

现场联调步骤：

1. 重启后端，刷新浏览器，发送普通问题。
2. 原任务仍在执行时，使用 Network 中复制的请求再次提交同一个 request_id，预期 HTTP 409 / PROCESSING。
3. 原任务仍在执行时，将复制请求的 request_id 改成新值，chat_id 保持相同，预期 HTTP 409 / CHAT_BUSY。
4. 原任务结束后再发送新问题，应正常执行。
5. 如果原任务已经结束，第 2 步可能再次执行，这是未接回放时的预期行为；选择实际执行时间足够长的测试问题。

## 当前限制

- 仅实现执行期间的排重，不保证任务完成后的重复请求幂等。成功回放下一阶段接入。
- 本地失锁检查已加入模型调用、流推进和关键保存操作，但检查与 PostgreSQL 写入不是原子操作，没有数据库 fencing；极端失联、进程暂停或 Redis 故障切换下，不能宣称严格 exactly-once。
- 已经发出的模型调用或 SQL 执行可能无法立即取消，返回后会检查执行资格。失锁任务可能留下未完成记录，目前不做自动补偿和人工恢复流程。
- Redis 未配置时应用可以启动，但受门禁保护的操作会返回 503；配置了 Redis 却连不上时应用启动失败。
