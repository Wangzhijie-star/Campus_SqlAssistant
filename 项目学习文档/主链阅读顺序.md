我觉得可以加的点不少，但如果你的目标是补 agent / tool / MCP 后端经验，我会优先选那些能真正碰到“工具编排、上下文管理、安全控制、可观测性”的功能。
最值得做的功能点
1. 把固定链路升级成轻量 Agent 执行器
   现在是固定流程：选数据源 -> 生成 SQL -> 查库 -> 生成图表。
   可以抽象成几个 tool：
   - select_datasource_tool
   - get_schema_tool
   - generate_sql_tool
   - validate_sql_tool
   - execute_sql_tool
   - generate_chart_tool
   - analyze_data_tool
   然后做一个 AgentRunner 统一调度。
   这会非常贴近真实 agent 开发经验。
2. SQL 自修复机制
   现在代码里已经会把上一次 SQL 错误塞回 prompt：last_execute_sql_error。
   可以进一步做成自动重试：
   - 第一次生成 SQL
   - 执行失败
   - 收集错误信息
   - 让模型基于错误修复 SQL
   - 最多重试 2 次
   - 每次重试写入执行日志
   这个功能很实用，也很适合练 “LLM + tool feedback loop”。
3. 查询计划 / 执行前解释
   在真正执行 SQL 前，先让模型给用户一句解释：
   我将查询订单表和客户表，按月份聚合销售额，并返回最近 12 个月趋势。
   
   或者后端生成一个 query_plan 字段。
   这能提升透明度，也方便用户发现模型理解错了。
4. SQL 风险评分
   虽然现在有只读校验，但可以加一个更细的风险层：
   - 是否全表扫描
   - 是否缺少 limit
   - 是否涉及大表
   - 是否跨多表 join
   - 是否用了复杂函数
   - 是否查询字段过多
   返回类似：
   {
     "risk": "medium",
     "reasons": ["可能扫描大表", "未命中时间过滤条件"]
   }
5. 数据源 schema 自动摘要
   当前 prompt 里塞的是表结构。可以加一个“表语义摘要”：
   - 这个表大概存什么业务数据
   - 常用字段是什么
   - 常见 join 关系是什么
   - 适合回答哪些问题
   摘要可以由模型离线生成，存到表元数据里。后续问答时比裸 schema 更好用。
6. MCP 工具增强
   现在 MCP 主要暴露问答、数据源列表、开始会话。可以加：
   - mcp_get_chat_record
   - mcp_get_record_data
   - mcp_get_record_sql
   - mcp_get_record_chart
   - mcp_export_excel
   - mcp_validate_sql
   - mcp_preview_datasource_schema
   这样外部 AI 客户端就不只是“问一次”，还能追踪结果、拿 SQL、拿数据、导出文件。
7. 问答执行详情可视化增强
   后端已经有 chat_log，可以把它变成更完整的 trace：
   - 每一步输入
   - 每一步输出
   - 调用了哪个模型
   - token 使用量
   - 耗时
   - 是否本地操作
   - 是否失败
   - SQL 执行行数
   这对 agent 调试非常关键。
8. 多轮上下文压缩
   现在会取最近几轮历史。可以加一个“对话摘要记忆”：
   - 当历史超过 N 轮，模型总结为 brief memory
   - 后续 prompt 只带摘要 + 最近几轮
   - 降低 token，提升长对话稳定性
9. 图表推荐优化
   当前是模型生成 chart JSON。可以增加规则兜底：
   - 1 个维度 + 1 个指标：柱状图
   - 时间字段 + 指标：折线图
   - 分类占比：饼图
   - 明细数据：表格
   - 多指标：组合图或多折线
   模型推荐 + 规则校验，会比纯模型更稳定。
10. 自然语言改图表
       比如用户问完后继续说：
换成折线图
只看华东区域
按季度展示
把销售额改成利润率

   后端可以识别这是基于上一条记录的“图表/SQL 修改任务”，而不是全新问题。
   这会很像 agent 的“基于状态继续操作”。
我最推荐你做的 3 个
如果你想边做边补经验，我建议顺序是：
1. SQL 自动修复重试
   最容易落地，而且能学到 tool feedback loop。
2. MCP 工具增强
   最贴近 MCP 开发经验，可以把已有能力包装成外部工具。
3. AgentRunner 抽象
   最能提升工程理解，把当前固定流程拆成 tool + step + trace。
这三个做完，你对这个项目的后端、LLM 调用、工具编排、MCP 暴露基本就都摸透了。
