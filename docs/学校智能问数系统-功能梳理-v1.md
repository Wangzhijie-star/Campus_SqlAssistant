# 学校智能问数系统：功能梳理 v1

本文基于 D:/SQLBot-main 当前源码静态核对，聚焦普通用户门户及其必要管理支撑，不展开 run_task() 内部调用链，不涉及助手与 MCP 改造。未运行系统做端到端验证。

标记说明：**已有**表示当前源码存在相应实现或接入；**一期约定**表示本次建议采用的产品范围；**待验证/建设**表示不能作为现有完成项。已有实现不等于权限、正确性已通过完整测试。

## 一、对原文档的评价

你已经掌握了以下功能关系：

1. 问数质量取决于业务知识和数据结构，不能只依赖模型理解自然语言。
2. 术语解释与 SQL 示例承担不同职责：前者提供业务口径，后者提供查询参考。
3. 检索应考虑用户范围与问题相关性，也需要控制上下文长度。
4. 多轮对话需要持久化，模型调用和中间产出需要可追踪。
5. 工作空间、数据源、业务知识、对话是需要分别建模的资源。

这些说明你已经建立了功能间的联系；但仅凭当前文档，还不能判断你已经掌握了模型调用实现、完整权限边界、异常处理或 Agent 编排。存储架构也仍需补齐实体关系，尤其是用户与工作空间、会话与问答记录、问答记录与步骤日志。

原文档主要有三个问题：将学校场景写成原项目背景；将已有功能、改造需求和探索性问题混写；重点放在生成 SQL 之前，遗漏执行查询、结果展示及结果正确性验收。

## 二、项目定位与一期范围

**原项目定位（已有）：** SQLBot 是基于大模型和 RAG 的通用智能问数系统，支持自然语言生成 SQL、查询数据、展示图表及进一步分析。学校业务不是原项目内置的领域模型。

**学校版本定位（一期约定）：** 面向学校中获得授权的学工、教学管理人员，提供学生成绩统计与学情分析。用户通过自然语言查询已接入的数据，并查看 SQL、数据结果、图表和分析说明。

原文中的“学生统计学生成绩”容易混淆使用者与数据对象。本版暂以教师、辅导员等业务人员为使用者，以学生成绩等数据为分析对象；学生本人自助查分若纳入，应另行定义角色与可见范围。

一期保留：普通用户登录与工作空间门户、Excel/CSV 和 MySQL 数据接入、表字段说明和关联关系、术语与 SQL 示例、多轮问数、SQL 与数据/图表展示、按需分析、日志与隔离验证。

必要管理支撑保留：账号、工作空间与成员、数据源、知识维护、大模型配置。聚焦普通用户体验不意味着删除管理能力，也不意味着向普通用户开放所有管理接口。

暂不纳入：助手、MCP、嵌入集成扩展、预测、仪表板扩展及其他数据库的专项适配。原项目支持更多数据源，但一期先以 MySQL 和表格导入为验收范围。

## 三、用户、工作空间与权限

### 3.1 工作空间门户

**已有：** 用户、工作空间以及用户—工作空间关联分别建模。用户可以关联多个工作空间；用户记录中的 oid 用于当前工作空间状态，不能据此认定用户只能属于一个空间。数据源、术语、SQL 示例和会话等资源包含工作空间归属。

**一期约定：** 工作空间先按学院或业务团队组织。普通用户进入当前空间后，只应访问其被授权的资源；无成员关系时不得通过修改请求参数进入其他空间。

这里的“门户隔离”包括页面展示和后端访问校验。仅隐藏菜单或在列表中按 oid 过滤，不能证明所有资源详情、查询、导出都已隔离。

### 3.2 三种边界分别定义

| 边界 | 学校例子 | 当前证据与要求 |
|---|---|---|
| 工作空间与资源归属 | 学院 A 与学院 B 的数据源和知识分别管理 | 已有模型和查询过滤；接口覆盖待验证 |
| 行权限 | 辅导员仅查看所带班级的记录 | 已有规则读取与 SQL 过滤接入；学校规则待配置和验收 |
| 列权限 | 某类用户不可见身份证号等字段 | 已有 Schema 字段过滤；不能仅据此保证最终 SQL 无法访问隐藏列 |

源码中 get_column_permission_fields() 会过滤字段；get_row_permission_filters() 会构造行过滤条件，问数流程还会调用模型处理带过滤条件的 SQL。当前代码也使用 SQL 解析检查生成 SQL 的表名范围。因此权限不能简单写成“放入提示词，让 AI 注意”。

注意：相关辅助函数中的 is_normal_user() 按用户 id 是否为 1 判断；这不是学校“教师、学生、组长”的角色模型。学校角色和权限映射属于待设计内容。

权限接口和部分模型依赖 sqlbot_xpack，本轮只核对仓库内调用点，未完整核实该依赖内部实现。不能据此承诺所有隔离路径已经安全。

## 四、数据接入与数据准备

### 4.1 数据库

**已有：** 保存数据库连接配置和表、字段元数据，通过数据库引擎执行查询。不能笼统写成“把 MySQL 数据全部存入本地召回库”。

**一期约定：** 管理人员配置 MySQL 数据源，验证连接，选择参与问数的表字段，并补充中文业务说明。普通用户使用准备好的数据源问数。

### 4.2 Excel/CSV

**已有：** 文件预览、工作表与字段类型处理，以及导入数据库的接口。导入目标使用配置的 PostgreSQL，之后作为可查询表使用；不是每次问数时将整个 Excel 直接交给模型读取。

当前 importToDb 接口要求 ws_admin 权限。如果希望普通用户自行上传，应列为角色权限和资源归属的新增改造，不能写成现状。

### 4.3 多表业务准备

**已有：** 表字段的选用设置、自定义注释、表关联关系；Schema 构造会包含字段类型、业务说明和关联信息。

**待建设：** 学号、课程号、学期等关联键的一致性；同一课程多次考试记录的粒度；空值、重复成绩和重复导入的处理规则。多张表能接入，不等于它们已经可以正确关联统计。

一期按“单个数据源内多表查询”组织数据。不把多个独立数据库、Excel 与 MySQL 的任意跨源联合查询视为已经具备的能力。

## 五、业务知识与召回

“数据库查询本地召回库”建议改称“业务知识与 Schema 检索”。这里至少有三类不同信息。

### 5.1 术语库

**已有：** 术语、解释、同义表达、启用状态，以及全空间适用或指定数据源适用的配置。检索包含文本匹配，开启 embedding 后还会执行向量相似度召回并去重。

**用途：** 将用户表达对应到业务含义和计算口径。术语库可以辅助理解字段，但不能替代真实表字段说明和关联关系。

**学校内容待建设：** 一次性通过率、曾挂科人数、尚不及格人数、学年平均每学期志愿时长等。

每个指标至少说明：统计对象、时间范围、去重单位、分子分母或聚合方式、补考/重修处理、空值处理和适用范围。例如“一次性通过率”必须明确是按人数还是选课人次计算，不能由模型自行决定。

“A 课程 50 分及格”应有可维护的数据或明确规则支撑；仅放一句术语描述不能保证所有课程统计正确。

### 5.2 SQL 示例库

**已有：** data_training 保存问题与参考内容，具有工作空间、数据源和启用状态。检索包含问题文本匹配及可选向量召回。参考内容作为 SQL 示例提供给模型。

这里的 training 不等于微调模型；当前查看到的是检索增强使用方式。

**一期约定：** 为核心指标维护经人工核实的问题—SQL 示例，并注明适用表结构与业务口径。表结构或口径变化时同步维护示例。

### 5.3 表结构检索

**已有：** 先构造候选表结构；启用选表向量功能时，按相似度排序并取配置数量的表，再根据已配置关系补充关联表。当前默认数量为 10，关联补全后可能超过该数量。

因此原文“去除拟合度低的表”应改为“按语义相似度筛选候选表并补充必要关联表”。这里不是统一相似度阈值淘汰规则，也不是只比较库表名称。

业务知识存在本地，不等于模型推理、embedding 计算或发给模型的内容一定不离开本机；具体取决于模型配置。

## 六、问数、上下文与提示词

### 6.1 用户可见功能

**已有：** 创建会话、提问、选择数据源（未确定时存在模型选择逻辑）、生成 SQL、执行查询、保存结果、生成图表，以及进一步分析、重新生成等能力。

**一期约定：** 用户能够查看查询结果和 SQL，并在当前会话继续追问；学情分析按需发起。SQL 统计结果与模型分析说明分别展示，避免将解释文本当成计算依据。

**待验收：** 数据源不可用、SQL 失败、查询为空等状态应清晰可见。不能仅以“模型返回内容”作为一次问数成功的判据。

### 6.2 上下文

**已有：** 会话和每次问答持久化；生成 SQL 和图表时会取历史消息，并按配置限制最近会话轮数。

应区分“保存了多少历史”和“本次发送了多少历史”。这不是自动记住所有历史，也不是跨会话的长期记忆系统。

### 6.3 提示词组成

**已有：** 角色与输出要求、数据库方言及 SQL 规则、表字段类型与说明、关联信息、样例数据、召回术语、SQL 示例、当前问题、时间，以及按配置保留的历史消息等。不同阶段使用不同模板。

**已有但有条件：** 自定义提示词存在接入，filter_custom_prompts() 受许可证有效性判断控制，且依赖 sqlbot_xpack；不能直接认定当前部署一定可用。

“确保 AI 注意每一个点”改为可验证目标：在固定的学校问题集上，检查是否使用正确字段、指标口径、时间范围和权限条件。提示词清晰有助于效果，但不是正确性保证。

## 七、日志、校验与回溯

### 7.1 现有分层

| 层次 | 主要用途 |
|---|---|
| chat | 一段会话的归属、标题和数据源等 |
| chat_record | 单次问题、SQL、执行结果、图表、分析、完成状态和错误等 |
| chat_log | 问答内步骤，包含操作类型、消息、时间、token 用量、错误及是否本地操作等 |
| sys_logs / sys_logs_resource | 管理操作审计及相关资源信息 |
| 应用运行日志 | 开发排障和运行过程记录 |

步骤日志中已有术语筛选、示例筛选、选表、模型生成和 SQL 执行等记录点。字段是否填充取决于步骤，例如本地 SQL 执行日志记录执行 SQL 和结果数量，并非保存完整数据库快照。

“回放”在本版指查看已有输入输出、定位失败步骤。重新运行并精确得到相同结果，还依赖模型版本、数据快照、规则版本等，不能视为现成能力。

### 7.2 一期校验与回溯要求（待验收）

| 位置 | 需要校验 | 需要能追溯的信息 |
|---|---|---|
| 资源访问 | 用户与空间、数据源、会话的访问关系 | 用户、空间、资源、拒绝原因 |
| 数据准备 | 表粒度、关联键、重复和字段类型 | 导入批次、表结构、数据处理规则 |
| 知识检索 | 适用范围与指标口径是否正确 | 命中术语、示例、候选 Schema |
| SQL 执行前 | 表列范围、行条件、可执行操作范围 | 原始生成内容、最终执行 SQL、检查结果 |
| 查询后 | 结果与人工基准是否一致 | 数据结果、行数、耗时、异常 |
| 展示与分析 | 图表字段和数值一致，说明有数据依据 | 图表配置、分析文本、关联问答记录 |

此表是验收要求，不代表每个检查与字段都已实现。日志也不能替代校验。

## 八、存储架构功能视图

| 数据类别 | 当前主要实体或位置 | 说明 |
|---|---|---|
| 用户与空间 | sys_user、sys_workspace、sys_user_ws | 账号、空间、多空间成员关系 |
| 数据源元数据 | core_datasource、core_table、core_field | 连接、空间归属、表字段说明及选用情况 |
| 业务数据 | 外部数据库；表格导入的 PostgreSQL 表 | 与用于召回的业务知识分开理解 |
| 术语 | terminology | 解释、同义表达关系、适用范围、向量 |
| SQL 示例 | data_training | 问题、参考内容、数据源、向量 |
| 会话与结果 | chat、chat_record | 会话归属及每轮问答产物 |
| 步骤日志 | chat_log | 本地步骤与模型步骤记录 |
| 管理审计 | sys_logs、sys_logs_resource | 谁对什么资源进行了何种操作 |
| 模型配置 | ai_model、ai_model_workspace_mapping | 模型配置及工作空间映射 |

术语和示例向量使用 PostgreSQL 的 pgvector 字段；表、数据源模型中的 embedding 为文本字段，不能统一画成一个独立向量数据库。缓存、文件保存和外部扩展模型不是本表的完整展开范围。

## 九、一期验收示例

以下是待执行验收，尚未证明通过：

1. 学院 A 用户无法通过页面和直接修改资源 ID 访问学院 B 的数据源、知识和会话结果。
2. 按首考、补考、重修等边界数据设计固定成绩样本，对“一次性通过率”等指标核对人工答案。
3. 同义问法应命中相同业务口径，计算结果一致。
4. 多表关联统计不因一对多连接重复计算学生人数。
5. 用户追问“只看上学期”，应正确继承指标并修改时间范围。
6. 配置的行列权限应覆盖问数、样例数据、结果查看及导出等相关路径。
7. 失败问答能关联到执行步骤和错误，不展示为正常完成。

## 十、源码依据与后续阅读入口

以下路径相对于仓库根目录 D:/SQLBot-main，仅用于支持功能核对：

- README.md：原项目定位。
- backend/apps/system/models/system_model.py：工作空间、成员映射、模型配置。
- backend/apps/system/models/user.py；backend/apps/system/crud/workspace.py：用户当前空间与关联空间处理。
- backend/apps/datasource/models/datasource.py：数据源与表字段元数据。
- backend/apps/datasource/api/datasource.py：表格预览、导入与接口权限声明。
- backend/apps/db/engine.py：表格导入使用的 PostgreSQL 引擎。
- backend/apps/datasource/crud/datasource.py：空间数据源列表、Schema、样例、关联补全。
- backend/apps/datasource/crud/permission.py：行列权限接入与普通用户判断。
- backend/apps/datasource/embedding/table_embedding.py：表相似度排序与数量限制。
- backend/apps/terminology/models/terminology_model.py；backend/apps/terminology/curd/terminology.py：术语模型、文本与向量检索。
- backend/apps/data_training/models/data_training_model.py；backend/apps/data_training/curd/data_training.py：SQL 示例及检索。
- backend/apps/chat/models/chat_model.py：会话、问答、步骤日志及提示词组成。
- backend/apps/chat/task/llm.py：功能编排、历史轮数、权限处理、SQL 表名检查和日志调用点。
- backend/common/audit/models/log_model.py：操作审计模型。
- backend/common/core/config.py：embedding 与选表配置。
- backend/pyproject.toml：sqlbot-xpack 依赖声明。

本版先建立功能边界。后续阅读可围绕一个具体问题，追踪“用了哪些业务口径、哪些表、生成了什么 SQL、如何判断结果正确”，再逐段定位实现。当前项目更适合先描述为“基于 LLM 与 RAG 的问数工作流”；是否采用某种自主 Agent 范式，应根据实际编排机制进一步说明。
