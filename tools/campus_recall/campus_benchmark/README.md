# 校园26术语评测 v1

## 范围

冻结2026-09-10 10:00的实际数据库快照：26主术语、28同义词，oid=1。200道合成题，不含真实学生个人信息。开发100、验证52、测试48。单术语104、多术语48、负例48。标签是初始设计，需要业务复核，尚未经过独立双人标注。多指标题采用模板表达，不能代表真实复杂多任务问答的难度。

同一术语的单问题表达、同一多指标组合、同一负例主题均作为一个组，不跨数据分组。各组覆盖的业务不同；比较方案要在同一分组上进行，不用开发分数与测试分数直接判断优劣。过去使用过的历史/当前两类单意图留在开发集。

最具体术语是严格目标。例如请求GPA班级排名不自动把GPA作为必要答案；请求通过率不自动把通过人数和有效成绩人数加入答案。额外父级术语在严格Precision中扣分，但不能直接认定它一定损害SQL生成。报告保留全部结果供复核。

## 第一次执行

在Ubuntu backend目录，启用.venv，运行：

```bash
python ../tools/campus_recall/campus_benchmark/run.py --check
python ../tools/campus_recall/campus_benchmark/run.py --split dev
```

如果快照不一致或源码回放不一致，脚本停止，不输出成功报告。保持数据库可用，模型目录可读取。页面无需参与测试。开发集会调用真实源码100次，另计算诊断向量；耗时取决于CPU，不是压力测试。

## 输出与方案

reports/dev-时间/report.json保存快照、源代码和题集哈希、原始结果、逐条词语匹配、完整向量排名、解释文本、网格和逐题指标。summary.md给出同参数对照。

- lexical：原SQL词语包含匹配。
- hybrid：原版混合召回，先阈值筛选、按记录取Top K、再归并主术语，合并词语结果。
- parents_only：同时从词语和向量分支排除同义词，主术语和原向量不变。不能据此估计每个具体别名的因果作用。
- description：保留全部54条记录，向量输入改为“记录名称。所属主术语解释”。在内存用余弦相似度计算；词语分支不变，不写回数据库。

默认开发/验证网格：阈值0.4、0.45、0.5、0.55、0.6、0.65；记录Top K=1、3、5、8、10。不能先归并再截断，那会改变原架构。词语包含匹配不受向量阈值过滤。

## 指标

Recall、Precision、全命中：只对正例宏平均。正例无返回时Recall/Precision记0。负例不进入这些分母。完全匹配统计所有题；negative_fp仅统计负例；multi_all_hit仅统计多术语题；avg_returned是平均主术语数。

这与旧脚本的混合分母Precision不同，不能将新旧Precision直接当成效果变化。

## 推荐流程

1. 先运行开发集；复核标签和典型错误，区分父级术语额外命中与真正冲突术语。
2. 根据场景明确最低召回覆盖和负例误召回要求，再在验证集比较预先确定的候选；没有通用合格分数。
3. 冻结一个策略和参数，再用`--split test --allow-test --strategy hybrid --threshold 数值 --top-k 数值`运行最终测试。test模式不运行参数网格。
4. 根据测试结果再调参时，此测试集应视为已用于开发；新的最终结论需要新题。
5. 单独的alias删除可用保存的rank/lexical_rows离线回放，区分别名命中、父级包含匹配和向量误匹配，形成管理员建议。

最终报告应区分“这批合成题观察到的收益”和“真实用户流量效果”。尚未验证SQL正确率、数据库查询结果和学校业务官方口径。
