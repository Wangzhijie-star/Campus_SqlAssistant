# 校园 SQL 示例召回评测（准备中）

目标：冻结 200 条「问题＋SQL」示例作为检索库，另外制作评测问题。已生成 corpus.json 和 200条SQL示例.md，完成200条本地适配执行检查；尚未运行 PostgreSQL 或真实召回，当前没有召回率结论。

## 当前产物与导入要求

- source_snapshot.json 保存四份实际 XLS 的文件哈希、字段和行数，不保存学生个人记录。第二行为表头，第一行为标题。
- 数据行数：曾不及格56、尚不及格21、成绩明细298、加权排名30。
- SQL 是 PostgreSQL 模板，{{history}}、{{current}}、{{detail}}、{{ranking}} 分别映射到四张导入后的表；不能将这些占位符直接入库。
- SQLBot 的 import_to_db 为每张表生成随机后缀物理表名，且 pd.read_excel 默认以第一行为表头。导入前需移除标题行，使实际字段成为第一行；四表必须属于同一测试数据源，才能进行跨表检索与查询。
- 学号、课程号、课序号按文本保留，防止前导零丢失。数值文本有空格；模板先去空格再转换。GPA排名是名次/总人数文本，模板读取斜杠前名次，不能整列直接转为数值。
- 导入后要用 COUNT(*) 对照上述数据行数。当前本地 import_to_db 源码在 df.to_sql 后又执行 COPY，存在重复写入的代码路径，实际 Ubuntu 版本需核对；评测前不能仅凭导入接口的 rows 字段确认数据量。
- sql_smoke_report.json：200/200 在内存 SQLite 加 SPLIT_PART/正则适配中执行通过，仅验证基础字段与查询可执行性；不能替代 PostgreSQL 类型/方言校验、业务结果正确性或 embedding 召回评测。
- metrics.py 已检查可替代ID、多意图、正例空返回、负例分母。评测问题及完整召回运行器尚未制作。

## 已确认的源码行为

- 入口：backend/apps/data_training/curd/data_training.py 的 select_training_by_question。
- save_embeddings 仅编码 question，SQL 存储在 description，不参与原版向量生成。
- 文本分支使用双向 ILIKE 包含匹配；百分号与下划线有通配符语义，诊断应使用真实 SQL 查询，不能简单用 Python in 模拟。
- 向量分支使用余弦相似度，严格大于阈值，再降序取 Top K；按 oid、enabled、datasource 或 advanced_application 隔离。
- 两分支合并后按 ID 去重，最终条数可能超过 K。
- 源码默认 0.4 / 5，实际运行配置需现场记录，不能沿用术语实验的 0.65 / 3。
- 最终返回 question 和 suggestion-answer，不含 ID，且读取详情没有 ORDER BY。应通过唯一问题和内容映射 ID，并单独保存向量排名；不能把最终结果顺序作为 MRR 的排名。

## 数据设计

已依据工作区四份学情分析 XLS 的真实表头设计字段。用户确认数据源将由 Excel 导入；导入后的物理表名和类型仍需现场绑定。SQL 以 PostgreSQL 为目标，与当前源码的 Excel 导入路径一致。

200 条示例应覆盖历史与当前挂科、成绩明细、加权成绩与排名等已有业务；覆盖明细、筛选、汇总、分组、排名、多表关联、存在/不存在、条件聚合及多意图。不要仅替换学期或班级数字凑数量。具体配额在确认 schema 后冻结。

示例记录：example_id、family_id、question、description（SQL）、业务口径、涉及表、enabled、数据源、审核状态。SQL 必须与业务标签一致，关联不能引入重复计数。

建议另建 200 道评测题：104 单意图、48 多意图、48 负例；按题族分开发100、验证52、测试48。同一题族的改写不得跨分组。整个固定示例库对所有分组可检索；划分的是评测题，不是分三份缩小候选库。

负例包括域外问题、同域但库中没有可用示例的问题。将示例原问题的精确查询另列为自检，不计入自然语言泛化分数。

标准答案使用 required_groups：[[E001,E002],[E080]] 表示第一意图 E001/E002 任一满足，第二意图还需 E080；[] 表示负例。可替代集合须业务复核。不能把所有相似示例都视为必须召回，也不能把存在关键业务口径冲突的示例视为正确。

## 执行与证据

1. 保存库快照、样例 ID 到数据库 ID 的映射、启用状态、数据源/组织、向量维度及空/非有限/零范数异常；记录语料、标签、源码哈希和实际模型配置。
2. 在隔离测试数据源或测试数据库导入审核后的 200 条，等待向量全部完成。明确现存示例是否为候选库的一部分，避免静默混入。
3. 逐题调用真实入口；保存最终 ID、真实文本命中 ID、全部向量相似度及排名、耗时和异常。向量失败后源码可能退回文本结果，必须单独报告，不能当作正常混合召回。
4. 校验离线回放与源码结果集合一致。Top K 边界同分须标记，原查询不保证同分次序。
5. 开发集比较文本、向量、原版混合。阈值与 K 网格只用于开发；验证集挑选固定候选，测试集仅比较基线与已冻结候选。
6. 汇总正例宏平均召回/精确率、多意图全命中率、全题完全满足且无额外返回率、负例误召回率；另报向量 Hit@K、MRR 及分题型结果。

metrics.py 对可替代示例按意图覆盖计算召回，精确率按正确 ID 占返回 ID 计算，负例单独计误召回。此处 exact 是「所有意图覆盖且无不相关示例」，并非术语 SOP 的唯一标准集合相等；报告必须明确口径差异。

召回质量与 SQL 执行正确性分开报告。SQL 需在已确认的 schema 上校验，合成标签未经业务复核时保留状态，不发布真实流量效果结论。
